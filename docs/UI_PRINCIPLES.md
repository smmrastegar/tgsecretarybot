# اصول UI/UX (قانون مالک — همه‌جا رعایت شود)

1. **محتوای کارت‌ها وسط‌چین است.** `Card` و `Section` به‌صورت پیش‌فرض `text-center` دارند؛ عنوان، توضیح و آمار وسط می‌آیند.
   فقط داده‌ی جدولی/فرم‌های چندستونه می‌توانند با `text-start` بیایند (در همان مورد، دلیلش را کامنت کن).
2. **همهٔ دکمه‌ها چپ‌چین‌اند** (چپِ فیزیکی، چه صفحه RTL باشد چه LTR). ردیفی که فقط دکمه دارد خودکار چپ می‌نشیند
   (قانون سراسری در `app/globals.css`: `justify-content: left`). دکمهٔ تمام‌عرض یا شبکهٔ دکمه‌ها مستثنی‌اند.
3. کف‌ها: متن لمسی ≥۱۲px، کنترل ≥۴۰px، بدون اسکرول افقی صفحه (`body{overflow-x:clip}`، `.grid>*{min-width:0}`).
4. الگو: فهرست ردیفی + `components/ui/Section.tsx` (تاشو، پیش‌فرض بسته) + شیت داخل برنامه به‌جای `confirm()/prompt()`.
5. هر صفحهٔ تازه یا بازطراحی‌شده را در عرض ۳۲۰ و ۳۹۰ بسنج؛ سرریز افقی = رد.

## الگوی صفحه (دستور کار بازطراحی)
- طراحی از موبایل ۳۹۰px شروع می‌شود؛ تأیید در ۳۲۰، ۳۹۰، ۷۶۸، ۱۲۸۰ (`document.documentElement.scrollWidth === clientWidth`).
- ساختار: `Shell` ← `PageTitle` ← (نوار خلاصهٔ اختیاری) ← جستجو/فیلتر ← فهرست به‌صورت کارت/ردیف (≥۵۶px).
  فرم‌های سنگین و تنظیمات پیشرفته داخل `components/ui/Section.tsx` (پیش‌فرض بسته). جدول روی موبایل = کارت‌های ردیفی.
- کارت‌ها وسط‌چین؛ دکمه‌ها چپ‌چین؛ هر دکمه ≥۴۰px؛ اقدام اصلی یکی و مشخص.
- حذف/عملیات خطرناک: `confirmDialog` از `components/ui/Dialogs.tsx` (نه `confirm()` بومی)؛ گرفتن متن: `promptDialog`.
- فهرست خالی: `components/ui/EmptyState.tsx` با گام بعدی؛ بارگذاری و خطا هم متن و دکمهٔ «تلاش دوباره» دارند.
- متن ≥۱۲px، اعداد فارسی با `fa()`، تاریخ محلی؛ هیچ رفتار/APIای عوض نمی‌شود (فقط ارائه).
